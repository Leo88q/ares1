# Связь колонии с экономикой POTATO — предложение

Статус: **предложение, не реализовано.** Код экономики, программа и backend в этом документе не меняются.

## 1. Что есть сейчас (факты из кода)

- Колония (`/base`) — локальный прототип. Бюджет **CR** (1 400 стартовых + до 240 CR от контракта 60 кг × 4 CR) живёт только в браузере и сбрасывается перезагрузкой.
- Колония не списывает и не выдаёт POTATO. Интерфейс прямо говорит: CR — не POTATO, SOL или деньги.
- On-chain операции колонии закрыты: `COLONIES_ENABLED=false` в backend, серверные гейты не ослаблялись.
- Единственный on-chain путь POTATO: поле → `harvest` (эмиссия под эпохальный кап) → траты (`pay_tax`, `repair_field`, `upgrade_field`, `apply_fertilizer`) сжигаются → рынок V1 (POTATO/SOL). V2 (POTATO/SKR) выключен по умолчанию.

## 2. Ограничения, которые нельзя обойти без решения владельца

| Источник | Правило |
| --- | --- |
| `COLONY_V1_PRODUCT_PROPOSAL.md` §47 | Нет автоматической эмиссии. |
| `COLONY_V1_PRODUCT_PROPOSAL.md` §63 | Ресурс колонии не превращается в SOL/SKR/POTATO и не переводится в токен. |
| Программа (`lib.rs`) | Каждая трата в игре — сжигание; эмиссия ограничена капом эпохи и `max_supply`. |
| Политика запуска | Mainnet fail-closed; любая программа и артефакт — через аудит и CI с Anchor. |

## 3. Варианты

**A. Прототип (статус-кво).** CR остаются локальными. Риска нет, но колония не влияет на экономику.

**B. Колония как сток POTATO (только сжигание). Рекомендуется.**
- Стройка, ремонт и апгрейды модулей оплачиваются POTATO с кошелька.
- Списание — новая инструкция `colony_spend`, которая сжигает POTATO тем же способом, что `pay_tax`. Новой эмиссии нет, кап эпохи не меняется.
- Соответствует существующим правилам: §47 и §63 не нарушаются, потому что ничего не выпускается и не конвертируется.
- Цены модулей в POTATO — продуктовое решение, в документе не задаются.

**C. Колония как источник POTATO (выпуск).** Требует нового пути эмиссии, решения по капу и отдельного аудита. Противоречит §47 и §63 без явного решения владельца. Не рекомендуется.

## 4. План для варианта B

1. **Программа (Rust):** инструкция `colony_spend(amount_micro, purpose)` с проверкой кошелька, паузы и лимитов, сжигание через существующий путь; IDL обновить; тесты Anchor. Проверка в CI: Rust 1.97.1, Solana 4.2.2, Anchor 0.31.2 (`cargo install anchor-cli --version "=0.31.2" --locked`).
2. **Backend:** по образцу покупок — order → подтверждённая транзакция → проверка сжигания → receipt (идемпотентно) → reconciliation при неопределённом статусе. Всё выключено флагом по умолчанию.
3. **Web:** в колонии цена в POTATO рядом с CR, баланс кошелька, кнопка подтверждения транзакции. Без подключённого кошелька — без трат.
4. **Тесты:** offchain-тесты обмена, backend-тесты идемпотентности, browser-smoke с мок-кошельком, проверка i18n.
5. **Запуск:** devnet-прогон → отдельное решение о mainnet (GO владельца).

## 5. Открытые вопросы владельцу

3. Нужна ли обратная связь (например, сбор POTATO из колонии) или только сток.
4. Допустим ли V1 (POTATO/SOL) как основной рынок до выпуска V2.
