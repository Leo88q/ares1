# Предложения: разделка урожая и труд на уборке

Два разрыва из §11, требующих решения по учёту массы. Ниже — что именно
происходит сейчас, почему так вышло, и варианты с ценой каждого.

## Что происходит сейчас

Обе цепочки читают **один и тот же** `ledger.rawKg`, но одна успевает первой.

```
грядка созрела
   │
   ├─ growBeds: rawKg += kg            (organism/unified.ts:228)
   │
   ├─ processDay: x = min(rawKg, 16.8) → processedKg += x·0.85
   │              │                      ─ organism/unified.ts:237
   │              └─ забирает ВСЁ: 16.8 кг/сол мощности против ~2 кг/сол уборки
   │
   └─ outbox.sort: видит rawKg ≈ 0 → applySort не вызывается никогда
                   ─ colony/deep/bridge.ts:501
```

**Корневая причина — не флаг `autoSort`.** Даже с `autoSort = true` глубокий
мир увидел бы ноль: `processorRateKgph = 0.7` даёт `16.8 кг/сол`
пропускной способности, а уборка в номинале даёт ~2 кг/сол в среднем.
Реестр осушает `rawKg` в тот же сол, когда он появился, поэтому
`sortableRawKg ≡ 0` и задача `process` не находит сырья.

Отсюда следствия, измеренные ранее: семена 35.85 → 13.29 кг за 180 солов
без возврата, `ware_potato = 0`, `sortedKg = 0`.

## Отдельный дефект: `applySort` создаёт массу

`colony/deep/world.ts:1756`, при `seedSplitShare = 0.12`, `cullShare = 0.08`:

```
seed    = 100 × 0.12              = 12
cull    = (100 − 12) × 0.08       =  7.04
ware    = 100 − 12 − 7.04         = 80.96
biomass = cull + 100 × 0.3        = 37.04      ← cull посчитан дважды
                                    ───────
                                    137.04 кг из 100 кг
```

Плюс мост отдельно делает `startCompost(harvestedKg × 0.3)`, то есть
растительные остатки уже учтены вне `applySort`. Формула не сходится, и
это надо исправить независимо от того, какой вариант выбран ниже: либо
`biomass = kg × 0.3` без `cull`, либо вычитать долю из `ware`.

## Главное ограничение для любого варианта

Возврат семян не берётся из воздуха. Сегодня еда = `0.85 × урожай`
(`processingYield`). Если 12 % уходит в семена, еда становится примерно
`0.75 × урожай` — минус ~12 % продовольствия.

Это важно: запас еды в номинале и так тонкий (минимум 35.3 кг на пике
между уборками). Любой вариант из этой заметки требует после этого
прогона трёх сценариев и, скорее всего, компенсации — площадью, нормой
посадки или меньшей долей семян.

## Разрыв 1. Разделка урожая не выполняется

### Вариант A — одна точка разделки в реестре (рекомендую)

`processDay` становится единственным местом, где урожай делится на
фракции. `applySort` и `outbox.sort` удаляются.

- `rawKg` → семена (0.12) → `seed_potato`; некондиция (0.08); товарная
  доля → `processedKg`; остатки → компост.
- Сумма фракций в точности равна входу.
- Глубокая задача `process` при желании становится **трудовым затвором**
  на эту разделку: `processDay` выполняется, только если люди отработали
  задачу в эти сутки.

**Плюсы:** одна модель вместо двух, масса сходится в одном месте,
склад семян замыкается, товарная партия появляется.
**Минусы:** правка `organism/unified.ts`, которым пользуется базовая
колония; минус ~12 % еды; нужна повторная балансировка.

### Вариант B — развести две цепочки последовательно

Сначала глубокий мир делит сырьё, потом реестр перерабатывает товарную
долю.

- Уборка → `rawKg`.
- Задача `process` (с включённым `autoSort`) делит `rawKg` →
  семена / товарная / некондиция / остатки.
- `processDay` читает не `rawKg`, а `ware_potato`.

**Плюсы:** каждый слой сохраняет свой словарь; разделка становится
видимой работой в очереди, как и требует задание.
**Минусы:** два слоя связываются через общий запас; если люди не дошли
до задачи, товарная доля остаётся нулевой и колония голодает — нужен
явный резервный путь. Самая высокая сложность из трёх.

### Вариант C — минимальный: замкнуть только семена

В `growBeds` при уборке часть урожая идёт в семена, остальное — как сейчас.

```
rawKg += kg × (1 − seedShare)      вместо  rawKg += kg
seedReturnedKg += kg × seedShare
```

Мост добавляет возврат в `seed_potato`.

**Плюсы:** одна строка в одном месте, масса сохраняется, утечка семян
закрыта, остальное не трогается. Легко откатить.
**Минусы:** товарной партии и некондиции по-прежнему нет; еда всё равно
теряет ~12 %; труд уборку по-прежнему не ограничивает.

**Рекомендация: C сейчас, A когда будет время на балансировку.** C
убирает самую неприятную часть (колония медленно съедает свой
невозобновляемый семенной фонд) ценой минимальной правки.

## Разрыв 2. Уборка не требует людей

Сейчас `growBeds` убирает созревшую грядку сам. Но там **уже есть**
механизм ожидания — грядка ждёт, если на складе нет места:

```ts
if (kg > freeKg(cur) + 1e-9) continue   // ждёт полного цикла, попробует завтра
```

Это и надо расширить, а не перестраивать поток массы.

### Вариант D — затвор по образцу существующего ожидания (рекомендую)

1. `planTasks` ставит задачу `harvest` на каждую созревшую грядку.
2. По завершении задачи мост помечает грядку готовой на эти сутки.
3. `growBeds` получает необязательный предикат `harvestAllow(plotId, bed)`
   рядом с существующим `yieldFactor` и добавляет его к условию ожидания.

Предикат необязательный: базовая колония его не передаёт и продолжает
работать как сейчас. Риск регресса минимален.

**Плюсы:** почти не трогает учёт массы; использует уже существующий
механизм ожидания; последствия осмысленны — если людей не хватает,
созревшая грядка стоит, копит стресс запущенности и теряет будущий
урожай. Это ровно та причинно-следственная цепочка, которую требует
задание.
**Минусы:** при перегруженном экипаже возможен разгон потерь. Смягчается
приоритетом уборки (уже 3) и тем, что стресс накапливается постепенно.

### Вариант E — списывать часы, но убирать автоматически (отвергаю)

Задача есть, время списывается, но урожай собирается независимо от неё.
Это учёт ради учёта: человек может не работать, а результат будет.
Именно такой паттерн я уже находил и исправлял в блоке B — не повторять.

## Что сделать до любой правки

1. Починить формулу `applySort` (создаёт 37 % массы) — либо удалить
   функцию, если разделка уезжает в реестр по варианту A.
2. Зафиксировать текущий минимум еды в трёх сценариях как отправную
   точку: номинал держится на 35.3 кг, и у вариантов A и C запас примерно
   на 12 % меньше.
3. Выбрать долю семян осознанно. `seedSplitShare = 0.12` — земная
   практика для продовольственного картофеля, но на Марсе её можно
   обосновать и подбирать под выживаемость.

## Порядок, если делать всё

```
1. applySort: починить массу                    (самостоятельно, без риска)
2. Вариант C: замкнуть семена                   (мало риска, убирает утечку)
3. Три сценария + балансировка еды              (обязательный шаг)
4. Вариант D: затвор уборки                     (отдельно, обратимо)
5. Вариант A: единая точка разделки             (когда есть запас по времени)
```

Шаги 1 и 2 дают главное: колония перестаёт проедать свой семенной фонд.
Шаг 4 закрывает критерий готовности про людей. Шаг 5 — архитектурная
чистота, без него можно жить.
