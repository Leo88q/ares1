# ARES-1 — единая концепция механик и экономики v1

Дата: 2026-10-14 · Для обсуждения · Цель: стыковка **существующей фермы (3 редкости, добыча 🥔)** + **нового слоя «Модули колонии»** в одну картину с числами и честным вердиктом.

---

## 0. Короткий вердикт (подробно — раздел9)

**Это не бред, но и не «полноценная крипто-игра» — пока.** В отличие от типичного токена-обманки, у проекта уже есть редкая вещь: **рабочий on-chain игровой цикл** (поля, урожай, износ, налог, мутации, рынок с escrow, комиссия, достижения, рефералы, лунный цикл) и **честный публичный чек-лист**, который прямо запрещает обещать доходность. Чего не хватает до «полноценной»: активного ядра (пилот-стройка ещё не в продукте) и **доказанного удержания** (нет D7-данных). Баллы — в разделе9.

## 3. Полная концепция игровых механик (как играет человек)

**Ядро цикла (1 вечер =1 решение):**
1. **Ферма** — поле копит 🥔 (on-chain, до7 дней накопления). Сбор =BASE.
2. **Стройка** — строим модули колонии на гриде: ставим → связываем (кабель/труба) → ресурсы
   колонии (⚡💧🍠🌬⭐) растут. Стоимость постройки списывается (см. §4).
3. **Связка ферма↔стройка (важно, см. §6):** стройка НЕ меняет on-chain урожай напрямую —
   она питает **сезонный вклад и призовый пул**; косметические бусты (мутации) остаются на ферме.
4. **Сезон** «Операция: Первая теплица»:4 главы (Посадка→Вода→Ремонт→Первый урожай) —
   каждая глава = серия задач из СУЩЕСТВУЮЩИХ действий (собрать/починить/улучшить/удобрить/
   сделка/достижение) **+ задачи стройки** (построй модуль главы, подключи сеть).
5. **Недельные спринты** стройки: общее семя-сетка, рейтинг «выход ресурсов / ⥠ стоимость»,
   топы делят **призовый пул** (финансируется сжигаемым, см. §4) — вход бесплатный (чек-лист).
6. **Рынок** — продаём поля/мутации/чертежи: fee9–12% (V2 — в SOL/SKR в казну).
7. **Прогрессия:** апгрейды полей (level1–50, мутации GOLD/SILI) + дерево модулей стройки;
   лаборатория (⭐ наука) открывает чертежи Rare/Epic.

**Что НЕ делаем (по чек-листу):** не требуем ежедневный вход (catch-up7 дней), не требуем
покупать токен для зачёта, не обещаем аирдроп/рост цены, вход в спринты бесплатный.

## 4. Экономика с цифрами

### 4.1 Источники (эмиссия) — база в коде

`DEFAULT_BASE_YIELD = 6 🥔/день` (L1, полная прочность, × global × луна0.85–1.15):

| Поле | 🥔/день (L1, средн. по луне) | Поля при L50 (макс.) |
|---|---|---|
| Common | ≈2.1 (1.8–2.4) | ≈43.8 |
| Rare | ≈6.0 (5.1–6.9) | ≈125 |
| Epic | ≈12.6 (10.7–14.5) | ≈263 |

Себестоимость полей: Common100 / Rare250 / Epic500 🥔 → **окупаемость40–50 дней**
(сезон28 дней — окупаемость НЕ внутри сезона: это удержание, а не печатка).

Апгрейд: `100×level×costBps` 🥔 → Common L1→L50 = 51 000 🥔 (огромный sink роста).
Налог (×0.5 урожая при неуплате), ремонт, удобрение — действующие sink'и уже в коде.

### 4.2 Новые потоки стройки (BURN/TRANSFER)

| Действие | Сумма (пример) | Распределение |
|---|---|---|
| Постройка модуля |60–300 🥔 (тир-цена) | **50% BURN + 50% призовый пул эпохи** |
| Экспресс-ускорение | ×1.5 стоимости | **100% BURN** |
| Провал редкого крафта (режим) | материалы | **100% BURN** |
| Демонтаж редкого модуля | возврат30% | **TRANSFER** из пула (не печать) |
| Приз недельного спринта | из пула | **TRANSFER** топ-10 |
| Финал сезона | статус/косметика | без токена (по чек-листу) |

**Ключевая петля:** стройка сжигает половину → из этой сожжённой половины (как из «страхового
фонда», не допечатывая!) финансируются призы = **чем активнее строят, тем сильнее burn,
и призовый пул растёт сжиганием, а не эмиссией.**

### 4.3 Потолки, чтобы не было инфляции

1. **Пул эпохи ≤20% эмиссии эпохи** (формула: `min(сумма строек×50%;0.2×эмиссия28д)`).
2. Пул одноразовый (раунд-ротация), остаток **в казну**, не копится на балансах игроков.
3. Еженедельный cap переводов из пула на кошелёк (анти-бот, как вклад-лимит чек-листа).
4. KPI-симуляция **burn/mint** по §5 чек-листа обязательна до V2 (уже стоит в чек-листе,
   потому что fee уходит из POTATO в SOL — главный legacy-источник burn сжимается).

### 4.4 Рабочий пример игрока (эпоха28 дней, реалистично)

Игрок:2 Common +1 Rare поля, L3–5, собирает раз в2 дня; строит10 модулей (60% Common).

- Эмиссия: ≈ (2×2.1 +1×6.0) ×28 ×1.1 (уровни) ≈ **207 🥔**.
- Существующие sink'и: налог ≈30, удобрения ≈60, апгрейды ≈150, ремонт ≈50 → **≈290 🥔**
  (уже сейчас расход ≥ эмиссии у активного игрока — **здоровый знак**).
- Стройка:10 модулей ×~130 средн. =1 300 → **650 BURN +650 пул**.
- Итог по токену: **BURN ≈650 против эмиссии207** — sink доминирует; пул650 распределяется
  по рейтингу (топы получают вклад, а не «проценты с баланса»).

*(Пример — модель для обсуждения; финальные числа — после симуляции burn/mint из чек-листа.)*

## 5. Как это ложится на сезоны и эпохи

- **28 дней =1 лунная эпоха =1 сезон** (уже в коде: LUNAR_TABLE, TAX_MAX_PREPAY28).
- Неделя =7 дней =4 спринта в эпоху (TAX_PERIOD7 уже есть).
- Глава сезона ≈7 дней: Посадка (стройка теплицы-модуля) → Вода (водный процессор) →
  Ремонт (буря/аварийный протокол → BURN) → Первый урожай (финал: общий счёт колонии).
- Луна×0.85–1.15 уже даёт «окна» для спринтов (пик дни5–9, провал19–23) — спринты можно
  привязать к фазам: стройка в провал (помощь), сбор в пик.

## 6. Инженерное решение: почему стройка НЕ трогает on-chain урожай (пока)

On-chain yield — глобальная конфиг-переменная (`base_yield`, `global_multiplier`). Сделать
**per-player** множитель от стройки = новый on-chain слой под аудит (и риск сломать
баланс эпохи). Поэтому:
- **M1–M3:** стройка влияет на сезонный вклад, призовый пул, косметику, чертежи — **всё
  через уже существующие `grant_reward`-вапучеры с подписью бэкенда** (утверждённый механизм);
- **M4 (после аудита):** опционально per-player бонус к yield по образцу существующих
  множителей — отдельным решением.

## 7. Дорожная карта стыковки

- **M0 ✅** — пилот стройки (визуал,6 моделей, BURN-петля) — сделано.
- **M1** — связность + тиры по таблице §2 + перекраска модулей в тир-цвета (серый/фиолет/оранж).
- **M2** — burn-хук на devnet (постройка →50/50 burn/пул), вапучеры `grant_reward`.
- **M3** — недельный спринт + лидерборд вклада (античит: серверный пересчёт).
- **M4** — сезон «Первая теплица» с4 главами (задачи фермы + стройки), финал без токена-обещаний.
- **M5** — (после аудита) per-player yield-бонус, POTATO/SKR, mainnet-гейты чек-листа.

## 8. Риски (честно)

1. **Retention неизмерен** — до D7/D7-данных любая экономика — теория (метрики §6 чек-листа).
2. **V2 fee в SOL/SKR** сокращает legacy burn в POTATO — обязателен прогон burn/mint-симуляции.
3. Стройка пока **вне продукта** (отдельный пилот) — стыковка возможна только после M2-M3.
4. Один разработчик; аудит, pinned-сборка, devnet-репетиция — launch gates ещё открыты.
5. Симбиоз «50% в пул» нужно защитить от сливания: пул — контракт-эскроу эпохи, а не баланс.

## 9. Вердикт: «полноценная крипто-игра или бред?»

**Оценка по слоям (честная):**

| Слой | Балл | Почему |
|---|---|---|
| Игровые механики | **7/10** | Богатый idle (износ/налог/мутации/луна), утверждённый сезон; активное ядро — прототип |
| Экономика | **6.5/10** | Реальные sink'и уже в коде (налог/ремонт/удобрения/апгрейды ≈ эмиссии); стройка добавляет честный burn; не хватает симуляции |
| Токен-логика | **7/10** | On-chain события, escrow, `grant_once`, никаких обещаний доходности — по меркам индустрии редкая честность |
| Удержание | **0/10 (нет данных)** | Главный риск: без D7 все таблицы — бумага |
| Продакшн | **5/10** | Devnet/аудит/Squads — launch gates открыты |

**Вывод:** «полноценная крипто-игра» = игра, **в которой токену есть зачем внутри правил**
(жгут по правилу, передают за результат), и **которую интересно играть без токена**.
Первое у ARES-1 уже есть (это НЕ бред и НЕ пустой токен). Второе — гипотеза, проверяемая
за один devnet-сезон. **Мой прогноз:** если M1–M3 выйдут и D7 на devnet ≥15% — проект
имеет шанс стать настоящей криптоигрой (механика + токен усиливают друг друга); если D7 <8% —
никакая экономика не спасёт, и честнее остановиться. Судить по удержанию, а не по коду.
