**Настоящая причина провалов деплоя — фича валидатора, а не клиент и не баланс.**
`solana-test-validator` в 4.2.2 включает все фичи, кроме `alpenglow`, в том числе
`disable_sbpf_v0_v1_v2_deployment` (`B8JJXCy5amZyWG9r7EnUYLwzXSXTxG7GZ1qZ1qggo83g`):
тогда `config.enabled_sbpf_versions = SBPFVersion::V3..=*`, и ELF, собранный
пиннутым тулчейном (SBPF v0-v2), отвергается с `Detected sbpf_version required by
the executable which are not enabled` → `invalid account data`
(`program-runtime/src/deploy.rs`, `morph_into_deployment_environment`). Калибровка
стартует валидатор с `--deactivate-feature B8JJXCy5…` и ждёт `solana cluster-version`
— конфигурация приводится к состоянию devnet. Гейт `anchor test` (ci.yml) этого
класса ошибок не видит: он встраивает программу в genesis (`--bpf-program`), а не
деплоит через loader-v3.

**Восстановление буфера по seed-фразе неавтоматизируемо** — `solana-keygen recover`
в 4.2.2 не имеет флага `--stdin` (фраза читается только с TTY), а сам CLI печатает
фразу лишь когда буфер не был передан (`if result.is_err() && !buffer_provided`).
Поэтому измерительный контур **не** полагается на фразу:

* обычный `program deploy` (буфер создаёт сам CLI) с `--max-sign-attempts 60`;
  при провале — до 3 свежих попыток, каждая со своим буфером; вариант со своим
  ключом буфера (`--buffer`, run 110483328229) в калибровке не используется;
* `execFileSync` с `maxBuffer` 256 МиБ; явная проверка результата деплоя; чтение
  аккаунта после деплоя — до 10 попыток;
* аннотация и при расхождении чеков (ветка `!pass`), не только при исключении;
* airdrop петлёй по 1 SOL до 40 SOL с проверкой, что баланс действительно вырос;
* `safeDiagnostic()` вычищает блок восстановления и 12+ слов подряд (R11), но
  первым делом фраза не должна попадать в вывод: если CLI её всё же напечатал,
  калибровка не сохраняет её (только пометку «напечатал seed-фразу»).

Тот же дефект был в `scripts/warm-start-devnet.sh` (продолжение по фразе через
`--stdin`) — исправлено: скрипт делает обычный деплой, а если CLI успел напечатать
фразу, сохраняет её в `target/deploy/.buffer-resume-$$.phrase` (umask 077, в
`.gitignore` через `target/`) и подсказывает человеку, как продолжить; флага
`--buffer` в скрипте нет.

**Отчёт CLI не равен измерению — и этому есть измеренная причина.**
Прогон `8fc8d25`: `solana program extend` завершился кодом 0 с текстом
«Extended Program Id … by 214968 bytes», но `space` и слот ProgramData,
прочитанные калибровкой, не менялись (то же и в финальном `deploy`). Причина —
**уровень подтверждения**: `getBalance`/`getAccountInfo` уходили без
`commitment`, то есть читались по умолчанию (`finalized`), а CLI сообщает по
`confirmed`; на localnet между ними десятки слотов, поэтому в чтении был
«успех без эффекта» и отрицательный расход в комиссиях (−18,2 SOL).
Исправлено: все чтения калибровки идут с
`commitment: 'confirmed'`, после каждого шага нужное состояние ожидается (до
30 с), а в payload печатаются обе точки — `confirmed` и `finalized`; в тестах
заглушка-сервер отвергает чтения без явного commitment. Сырая ExtendProgram
транзакция с ручной подписью, добавленная в `2622c32`, удалена: она была
лечением симптома (и сама по себе упёрлась в `invalid instruction data`, потому
что формат данных зависит от версии SDK).

5 080 лампортов (0,00000508 SOL)**, то есть 227 017 Б ≈ **1,15 SOL**;
1 КиБ ≈ 5 201 920 лампортов ≈ **0,0052 SOL**. Пример для вопросов человеку:
«минус 64 КиБ = минус 0,33 SOL», «минус 128 КиБ = минус 0,67 SOL».

> **Ответ (0.5, одной строкой):** при ставке **5080** уровень A **не достигнут**:
> минимальный измеренный `NEED_TOTAL` — **4,1551 SOL** (первый деплой, профиль
> `opt-level=z`, 756 424 Б), апгрейд — 4,3647 SOL; до уровня A не хватает
> **227 017 Б сокращения `.so` относительно z (−30 %, нужно ≤ 529 407)**.
>
> **Ликвидность (не экономия NEED):** на деплоере висят застрявшие буферы
> (~10 аккаунтов, ≈ **33,57 SOL** по данным владельца) — это уже потраченный
> залог, который можно вернуть (`program close --buffers`); сумма пересчитывается
> скриптом `warm-start-devnet.sh` при каждом запуске (шаг 2/7) и **не уменьшает
> NEED_TOTAL**. Точная сумма подлежит измерению перед возвратом (Q5).

## ОТКЛОНЕНИЯ от §1–§2

1. **Размер `.so`.** §2 ожидал 0,4–0,5 МБ (косвенно, по zip-артефакту и
   комментарию «~3.45 SOL»). Измерено **971 392 Б** — вдвое больше; отсюда
   уровни A/B по таблицам §2 недостижимы даже профилем `z` (756 424 Б).
2. **Ставка devnet = 5080** — подтверждена измерением (шаг 2 SIMD-0437),
   `rateMatchesDelta = true`.
3. **Версия кластера 4.3.0** при запиненном CLI 4.2.2 (не влияет на расчёт:
   ставка читается из RPC).
4. **`solana program show` требует signer'а даже для чтения** («No default signer
   found») — зонд переведён на чистый RPC (без ключей).
5. **`getEpochInfo` в Agave 4.3.0 не содержит поля `slot`** — зонд печатает
   `slotIndex`/`slotsInEpoch`/`absoluteSlot`.
6. **Config на devnet в легаси-раскладке**: `config260 = 0`, `config164 = 1`
   (текущий код ожидает 260). Это подтверждает живой сценарий для группы
   миграций и запрещает молчаливый bootstrap (вопрос Q2).
7. `require!` 127 — по всему файлу; в боевом коде 120. `remaining_accounts` 17,
   не 18.
8. Открытых PR 22, а не 6+.

| Что | Причина |
|---|---|
| `48D2…`: authority, `dataLen`, `lamports` | полного адреса нет в репозитории (Q1); зонд печатает `{"measured":false}` |

| Калибровка §5.7 (залог на живом валидаторе) | попытка №1 упала на попытках подписи (см. §0.6); исправлено, перезапуск — следующим пушем (job `calibrate-localnet`) |
