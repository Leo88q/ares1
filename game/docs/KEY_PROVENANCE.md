# Происхождение ключей (key provenance) — пп. 99 и 126

**Прецеденты.** Ill Bloom (10.07.2026, >$5M) — кошельки игроков/команд,
сгенерированные слабой энтропией; SecondFi/Yoroi (23.06.2026, $2.4M с 178
кошельков, ещё $20M под риском) — то же. Coldcard (с 30.07.2026): ошибка сборки
прошивки с марта 2021 откатывала генератор сидов на слабый программный ГСЧ —
эффективная энтропия ≈40 бит (Mk2/Mk3) и ≈72 бита (Mk4/Mk5/Q); за несколько
волн выведено порядка 1.4–1.8 тыс. BTC; **все опустошённые кошельки первой
волны были single-signature**; обновление прошивки уже созданные сиды не лечит.

**Правило проекта:** у каждого ключа, способного подписывать что-либо ценное
(authority, guardian, reward_signer, казна, резервные), есть запись
происхождения: кем, когда, на чём и в какой версии ПО создан. Ключ без записи
считается скомпрометированным по умолчанию.

## 1. Как генерировать (единственные допустимые способы)

1. **solana-keygen на чистой офлайн-машине** (live-USB, без сети):
   `solana-keygen new --no-bip39-passphrase --silent --outfile keys/<role>.json`
   — или с bip39-фразой, если нужен человеческий backup, записанной на бумагу.
2. **Аппаратный кошелёк** (Ledger/Trezor/Coldcard) — для authority/казны.
   Перед первой генерацией — проверить версию прошивки против списка
   известных уязвимостей производителя (урок Coldcard: уязвимая прошивка
   = уязвимые сиды навсегда).
3. **Для критичных authority — добавить собственную энтропию**: при генерации
   использовать bip39-мнемонику, дополненную монеткой/кости, а не только ГСЧ
   устройства.

Запрещено: самописные генераторы, vanity-грайндеры из непроверенных источников,
генерация на рабочем ноутбуке/CI, `Keypair.generate()` в браузере для чего-либо,
кроме одноразовых devnet-кошельков игроков (их баланс — только их собственный).

## 2. Реестр происхождения (заполняется для каждого ключа)

Хранится приватно (не в git). Публичен только факт «запись есть и актуальна».

| Поле | Значение |
|---|---|
| Роль | authority / guardian / reward_signer / payer / treasury-N |
| Адрес (публичный) | `TBD` |
| Создан | дата, кем (инициалы) |
| Способ | solana-keygen vX.Y на offline-машине / Ledger Nano S+ fw X.Y.Z / ... |

## 3. Порог энтропии и тесты

- Ключи из затронутых версий прошивок/ПО считаются **скомпрометированными
  независимо от того, что балансы ещё не тронуты** (Coldcard: выводили
  волнами, неделями позже).
- Если есть подозрение на слабую энтропию (старый генератор, чужая утилита):
  миграция на новый ключ + отзыв старого обязательны; для authority — через
  `propose_authority` → `accept_authority`.
- Проверка «дурацких» ключей перед интеграцией чужого контента (тестовые
  задания рекрутёров, демо-репозитории): никогда не запускать их keypair-
  утилиты (см. OPERATIONS, «Люди, устройства и доступ»).

## 4. Мультисиг с независимой энтропией

Для authority/казны — Squads ≥ 3 из N, где:
- ≥ 3 разных ФИЗИЧЕСКИХ устройства (не копии одного seed);
- разные производители/прошивки там, где возможно;
- подписанты в разных местах (см. wrench-атаки, п. 125) и на разных ОС;
- ни один seed не дублируется между подписантами.

Процедура при компрометации одного подписанта описана в
[INCIDENT_RESPONSE.md](INCIDENT_RESPONSE.md) §3 (ротация authority).
