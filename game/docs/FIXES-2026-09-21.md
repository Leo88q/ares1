## Критические

### C-1 — Один authority-ключ, безлимитные выводы казны ✅🟠📋
- ✅ Rate-limit выводов через новый PDA `AdminState` (seeds `["admin_state"]`,
  97 B): **250 000 🥔 / 25 SOL / 100 000 SKR на скользящее 24-часовое окно**
  (`roll_withdraw_window`). Все три `withdraw_*` создают AdminState лениво
  (`init_if_needed`, payer = authority). Превышение → `WithdrawWindowLimitExceeded` (6036).
- ✅ Чувствительные admin-изменения переведены в двухшаговый **24-часовой
  тимелок** (`ADMIN_UPDATE_TIMELOCK_SECONDS`): `update_skr_mint` →
  `apply_pending_skr_mint`, `update_presale_price(>0)` →
  `apply_pending_presale_price`. Ошибки: `TimelockNotExpired` (6038),
  `NothingPending` (6039).
- ✅ Kill switch пресейла: `update_presale_price(0)` применяется мгновенно и
  закрывает оба рельса (единственное исключение из тимелока — остановка, а не
  изменение в пользу admin).
- 📋 Мультисиг (Squads 2/3+) на game authority и upgrade authority, алерты на
  `TreasuryWithdrawn/PausedToggled/AuthorityProposed/ConfigUpdated` — задача
  деплоя (watchtower события уже покрывает). Код не может сам себя
  децентрализовать: перед mainnet authority должна быть передана мультисигу
  через `propose_authority/accept_authority`.

### C-2 — Безлимитная эмиссия через `grant_reward` ✅
- ✅ Квота ручных грантов: суммарно ≤ `GRANT_QUOTA_SHARE_BPS` = **10 % капа
  эпохи**, трекается в `Epoch.granted_micro` (переименовано из мёртвого
  `burned_micro`, layout 49 B не изменился). Превышение →
  `GrantQuotaExceeded` (6035). ≥90 % капа каждой эпохи гарантированно остаются
  под harvest игроков — сценарий DoS «750 tx по 1000 🥔 сразу после roll_epoch»
  больше не исчерпывает кап.
- Лимит 1000 🥔/tx сохранён. 📋 reward_signer — изолированный кошелёк низкого
  доверия (уже требовался B4), ротация; теперь его компрометация ограничена
  10 % дневного капа.

## Высокие

### H-1 — `buy_field_sol`: EPIC-поля по 0.25 SOL по выбору покупателя ✅
- ✅ Выбран вариант аудита «дифференцировать SOL-цену по типу»: цена =
  `price_lamports × type_cost_bps` (0.4× / 1× / 2×, та же таблица, что для
  POTATO-цен). EPIC больше не дешевле create_field-синка.
- ✅ Тир по-прежнему определяется on-chain роллом (как в `buy_field_skr`).
- ✅ Новый аргумент `max_total_lamports` — slippage-guard покупателя: если
  цена поднята после подписания, tx падает с `InvalidPrice` (закрывает и
  фронт-раннинг из M-1a).

### H-2 — Предсказуемый RNG (presale-ролл и мутация апгрейда) 🟠
- ✅ Компенсация без внешних оракулов: оба ролла дополнительно хешируют
  новейшую запись sysvar **`SlotHashes`** — `keccak(keccak(buyer‖sold‖slot) ‖
  recent_slot ‖ recent_hash)` для presale-дропа (`buy_field_skr`) и
  `keccak(field_key‖slot ‖ recent_slot ‖ recent_hash)` для мутации (`upgrade_field`).
  Хеш слота включения неизвестен в момент подписания → grind «купи в слоте N
  ради гарантированного EPIC/Golden» со стороны игрока не проходит.
- ✅ **Исправлено 21.09 (важно):** первая реализация прокидывала sysvar как
  типизированный `Sysvar<SlotHashes>`, но `SlotHashes::from_account_info`/`get`
  on-chain **всегда** возвращают `UnsupportedSysvar` (sysvar слишком велик для
  bincode-декода в программе) → Anchor отдавал `AccountSysvarMismatch` (3015):
  `upgrade_field` и `buy_field_skr` в принципе не исполнялись на валидаторе
  (падал и `anchor test`). Теперь sysvar передаётся как `UncheckedAccount` с
  `#[account(address = SysvarS1otHashes…)]` (key жёстко закреплён), а новейшая
  запись читается partial-декодом из сырых данных в приватном хелпере
  `recent_slot_hash` (`[0..8]`=count, `[8..16]`=slot, `[16..48]`=hash; полный
  bincode-декод не влезает в CU-бюджет). Формулы энтропии не изменились. У
  `buy_field_sol` slot_hashes **нет**: там тир выбирается явно и оплачивается
  по типу (H-1), ролла нет.
- 🟠 Побочный эффект фикса: Anchor **не** эмитирует поле `address` в IDL для
  `UncheckedAccount` (в отличие от `Sysvar<T>`), поэтому `slot_hashes` потерял
  `address` в `apps/web/src/idl.json` (новый sha `b092c974…1177`). On-chain key
  по-прежнему закреплён address-констрейнтом; браузерные raw-builders и
  `tests/solana_potato.ts` и так пинят `SYSVAR_SLOT_HASHES_PUBKEY` явно, а
  offchain ABI-тест (`clientAbi.test.ts`) теперь сопоставляет `slot_hashes` с
  sysvar-константой напрямую, а не через IDL-`address`.
- 🟠 Остаточный риск (задокументирован): лидер слота/валидатор знает
  SlotHashes до включения tx. Полное устранение — VRF (Switchboard/ORAO) или
  commit-reveal; оставлено как roadmap-задача (зависимость + стоимость tx).
- ✅ Клиентские зеркала обновлены (web/landing/backend raw-builders добавляют
  sysvar-аккаунт).

### H-3 — 48-часовое сгорание начисления + гонка за кап 🟠📝
- ✅ `MAX_ACCRUAL_SECONDS`: 48 ч → **7 суток** — начисление больше не сгорает
  за выходные; у казуала 7 дней, чтобы забрать долю капа.
- ✅ Взаимодействует с M-8 (взвешенная луна): перенос начисления через эпохи
  больше не создаёт лунный арбитраж.
- 📝 First-come-first-served распределение капа сохранено сознательно:
  пер-field квоты — изменение экономической модели (отдельное решение владельца,
  см. ECONOMY.md §8.3). Частичное начисление по-прежнему переносится
  (`last_harvest` сдвигается пропорционально выплате).

### H-4 — Гонка bootstrap: перехват `initialize` ✅
- ✅ `scripts/init-onchain.ts`: createAccount → initializeMint(6, admin,
  **без freeze**) → setAuthority(mint → config PDA) → `initialize` →
  `init_epoch` теперь выполняются **одной атомарной транзакцией**
  (signers: admin + свежий mint keypair). Окна, в котором наблюдатель может
  вызвать `initialize` с легитимным минтом и стать authority, больше нет.

### H-5 — Утёкший RPC-credential 📋
- В текущем дереве секретов нет (gitleaks CI + `.gitleaks.toml` сохранены).

### H-6 — `base_yield` без верхнего предела; cap-конфиг не управляет roll_epoch ✅
- ✅ `MAX_BASE_YIELD_MICRO_PER_DAY = 100 🥔/день` — `update_config` отклоняет

- ✅ Clamp `roll_epoch` привязан к конфигу: `[daily_mint_cap_micro,
  3×daily_mint_cap_micro]` вместо жёстких 250k–750k — админ-настройка
  `daily_mint_cap_micro` стала реальным рычагом (в т.ч. аварийным снижением).
